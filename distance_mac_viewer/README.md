# EE3070 测距与组件测试 · macOS

在同一个 Chrome 页面中，通过一条 Pico USB 串口读取 TFmini-S、前方 HC-SR04 和上方 HC-SR04，并测试马达、蜂鸣器、COB 灯、板载 LED 和四个按键。网页资源均在本机；Mac 侧需要 Python 3.9 或更新版本和 Google Chrome，无需安装 Python 第三方库。Pico 侧需要 MicroPython。

## 启动

1. 解压整个文件夹，保留各文件在同一目录中。
2. 关闭原 TFmini 页面、超声波页面、Thonny、串口监视器等对 Pico 的串口连接。
3. 将 Pico 通过 USB 数据线连接 Mac，并按接线图为三个传感器供电。
4. 双击 `start_distance_mac.command`，保持弹出的终端窗口开启。
5. 在自动打开的 **Google Chrome** 页面中点击“连接 Pico”，选择 Pico / USB Serial。

如果 macOS 不允许直接打开启动文件，可在终端执行：

```sh
cd "/解压后文件夹的完整路径/distance_mac_viewer"
bash start_distance_mac.command
```

也可运行 `python3 distance_mac_server.py`。服务仅监听 `127.0.0.1`，每次选择空闲端口；网页地址以终端输出为准。请通过这个地址打开页面。

## 两种连接方式

- **临时运行测距与测试程序（默认）**：发送 Ctrl-C 暂停 Pico 当前程序，将 `pico_diagnostics.py` 与 `distance_pico_stream.py` 一起在 RAM 中执行，同时采集三路数据并等待测试指令。不会写入 `main.py` 或修改板内文件。断开时停止本次程序并关闭输出；重新插拔 Pico 可恢复板内原有启动程序。如果原程序仅在 RAM 中，重新插拔不会恢复那段临时代码。
- **只接收现有程序的数据**：不发送任何命令，组件测试按钮禁用。板内现有程序须输出下述 `TF_DATA` / `US_DATA` 协议中相应的记录；任一模块无数据时，另一模块仍可显示。页面不能直接解析任意旧程序输出。

**同一个 Pico 串口只交给一个页面或软件使用。** 此页面已经同时读取 TFmini 和两个超声波，无需同时连接原来的 TFmini 页面。

## 组件测试

连接后等待“测试已就绪”，直接点击对应动作。一次运行一项，点击“立即停止”可提前关闭；前端显示执行回执、倒计时和最近记录。回执表示程序执行，不自动将组件记为实物通过。

| 按钮 | 固定动作 | 接线 |
|---|---|---|
| 马达振动 | 全开 5 秒 | GP14，经 U1/Q1 驱动；U2 输出按已确认的 3V 设置 |
| 蜂鸣器响 | 3kHz、50% PWM，5 秒 | GP16，经 Q2 驱动；采用现场试听选择的频率 |
| COB 灯亮 | 全开 3 秒 | GP15，经 U1/MOS 模块驱动 |
| 板载 LED 闪烁 | 每 0.5 秒亮灭，共 3 秒 | GP25，USB 接口旁的小绿灯 |
| 按键检测 | 采集 45 秒，显示按下、松开和长按 | K1–K4 对应 GP10–13，内部上拉，按下接地 |
| 立即停止 | 关闭当前测试及全部输出 | GP14/15/16/25 |

按键尚未接好时，暂不启动按键检测。树莓派上的 MPU6050、摄像头和音频组件不属于本页控制范围。

Pico 使用 50ms 硬定时器检查测试到时和心跳：测试中网页每 500ms 发送心跳，连续 2.5 秒未收到即关闭输出。关闭不依赖网页倒计时；Ctrl-C/finally 也会关闭输出。相关 API 采用 [MicroPython v1.29 的 RP2 Timer](https://docs.micropython.org/en/v1.29.0/rp2/quickref.html#timers)。演示模式不控制实物。

测试使用 `HW_CMD,id,target,duration_ms` 换行指令；只有上表固定时长可执行，不接受任意 GPIO 或提高电压的指令。Pico 回报 `HW_READY,1`、`HW_DATA,JSON` 和 `HW_BUTTON,JSON`；这些记录不混入测距 CSV。单独运行 `distance_pico_stream.py` 仍可只测距；网页会自动将诊断类放在它前面一起运行。

## 默认接线

按用户提供的 `ee3070-complete-direct-wiring(1)(1).pdf` 第 1 页：

| 传感器 | 信号连接 | 供电 |
|---|---|---|
| TFmini-S | 白 RXD → Pico GP8 / UART1 TX（物理 11）；绿 TXD → Pico GP9 / UART1 RX（物理 12） | 红线 → 5V_AUX；黑线 → 共地 |
| 前方 HC-SR04 | Trig：GP2（物理 4）经 U1 1A/1Y；Echo：经 R1/R2 分压至 GP3（物理 5） | 5V_AUX / 共地 |
| 上方 HC-SR04 | Trig：GP4（物理 6）经 U1 2A/2Y；Echo：经 R3/R4 分压至 GP5（物理 7） | 5V_AUX / 共地 |

TFmini 使用 **UART1，115200 / 8N1**。U1 为 **SN74AHCT125N**，5V 供电、对应 `/OE` 接地，用于超声波 Trig 电平转换。每路 Echo 分压为 **2.2kΩ 串联、3.3kΩ 接地**。HC-SR04 的 5V Echo 不能直接连接 Pico GPIO。接线图注明其设计尚未经实物通电验证，软件验证不能代替核线。

## 读数、单位与时间

- TFmini 显示距离、原始距离值和 strength。距离原始单位默认按 **cm** 解释；如果传感器已配置为毫米输出，将页面 TFmini 单位切换为 **mm**。此选项只改变 TFmini 的换算，不改变传感器配置，也不改变超声波换算。
- TFmini 沿用原查看器的有效性规则：原始距离 0 / 65532 / 65534 / 65535、strength < 100 或 strength = 65535 时无效；换算后小于 10 cm 或大于 1200 cm 也不作为有效距离。无效值显示 `—` 并在曲线中留空，不能据此确定测量误差或精度。
- 超声波按声速 343 m/s 换算：`cm = echo_us × 0.0343 / 2`。显示小数位不代表测量精度；未做温度补偿。无效脉宽和超时显示为 `—`。
- 两个超声波依次触发，触发间隔至少 80 ms，减少串扰；两路并非同时测量。
- TFmini 的 Pico 时间为 **解析该帧的 `ticks_us()`**；其间隔是相邻解析时刻之差。超声波采集会阻塞代码，UART 缓存中可能积累多帧并随后集中解析，因此这个间隔**不等于 TFmini 的真实采样间隔**，不能据此声称传感器采样频率。
- 超声波 Pico 时间为完成整组采集的 `ticks_ms()`。它与 TFmini 的微秒时间字段使用不同单位；两种 ticks 均可回绕。
- 电脑接收时间是浏览器接收数据的时刻，也可能受 USB 分包和批量接收影响。实时图表和 CSV 用于观察、记录数据，不能代替测距精度校准。
- “查看演示”使用明确标记的模拟数据，不读取 USB；演示结果不代表硬件验证。
- 三路各自检测断流，超过 1.5 秒未收到该路记录会清除其当前距离。仅有某一路超时不会影响其余通道。
- 曲线保留 30 秒，可独立勾选通道；CSV 保留最近 10,000 条原始记录，按 TF / US 独立行导出，不拼接成同步测量。改变 TF 原始单位会清空激光曲线；CSV 每行保留采集时选择的 TF 单位。

## USB 输出协议

USB 打开参数为 115200 / 8N1，UTF-8，每条记录以换行结尾。两种记录在同一串口中交错输出：

```text
TF_DATA,1000000,-1,120,450
US_DATA,1,1080,5831,11662
TF_DATA,1082000,82000,121,448
```

| 记录 | 字段顺序 |
|---|---|
| TF_DATA | 标记、Pico 解析时刻 `ticks_us`、与上一帧解析时刻的间隔 `delta_us`、原始距离 `raw`、信号强度 `strength` |
| US_DATA | 标记、正整数序号 `seq`、整组完成时刻 `ticks_ms`、前方 Echo 微秒 `front_us`、上方 Echo 微秒 `upper_us` |

TFmini 第一帧的 `delta_us` 为 -1。超声波 `-2` 表示等待回波上升沿超时，`-1` 表示高电平测量超时或采集前 Echo 持续高电平；0 为无效脉宽。页面忽略与协议无关的启动提示、回显代码和不完整行，按完整换行解析 USB 分包。

这里的 `TF_DATA` 是 Pico 对 TFmini UART 二进制帧解析后产生的 USB 文本协议。TFmini 仍通过 GP8/GP9 使用它本身的 UART 协议。

## 故障排查

- 没有串口选项：确认使用电脑 Google Chrome，USB 线支持数据，Pico 已安装 MicroPython。
- 端口打不开：断开其他页面、Thonny 等软件的串口连接，再连接本页面。
- 无法进入粘贴模式：查看“串口诊断”，确认 Pico 运行的是 MicroPython。
- TFmini 无数据：检查红黑供电、共地、绿 TXD → GP9、白 RXD → GP8，核对 UART1 的 115200 / 8N1 和 TFmini 输出配置。
- TFmini 距离相差约 10 倍：核对传感器实际输出单位，选择正确的 cm 或 mm；不要通过改变超声波系数补偿。
- 某个超声波没有回波：检查该路供电、共地、Trig 电平转换及 Echo 分压，在传感器正前方放平整目标。
- “只接收”模式没有更新：原程序必须持续输出以上协议；该模式不会启动采集程序。
