|---|---|---|

本阶段不包含麦克风交互、地图导航或自由聊天。GY-521 尚未形成可验收的坡度功能；不能把拐杖自身姿态直接等同于地面坡度，也不能当作楼梯高度或落差测量。

## 二、当前已整合能力

| 功能 | 已实现内容 | 边界 |
|---|---|---|
| 摄像头与网页 | 单路取流、最新帧共享、画面预览、识别区域、状态和诊断接口 | Pi 实测采集约 14.9 FPS，电脑预览约 11.8 FPS；安装后的移动识别待测 |
| 积水 | 检测候选后进行图像场景复核，再进入提醒规则 | 仍有漏报与少量误报；不是水深测量 |
| 坑洞 | 专用模型检测，结合地面上下文、前方区域与连续确认 | 仍有漏报；积水等外观可能误识别成坑洞 |
| 裂损路面 | 检测可见裂纹、破碎表面 | 当前效果较弱；不等于真实高低不平、下陷深度或突然落差 |
| 楼梯 | 语义分割结合场景复核，覆盖室内外上行／下行楼梯图片 | 统一生成 “Possible stairs ahead.”；未启用上下行方向区分 |
| 普通物体 | balanced 模式保留人、椅子、包等识别框 | 默认 ground 模式关闭普通物体模型；普通物体提醒受距离门控 |
| 英语声音链路 | 固定语音片段、优先级调度、重复控制、过期提示丢弃 | 旧版本在 Pi + HyperX 耳机上曾验证；本次未插接收器，按用户选择关闭声音 |
| 误报控制 | 场景复核、前方关注区域、两次不同观测确认、冷却与持续目标去重 | 不保证消除所有误报；候选分数不等于真实正确率 |
| 测试与复核页面 | 显示真实候选、拒绝原因、最终提醒事件及素材来源 | 某一帧的候选状态与整段测试最终结果属于不同时间点 |

当前默认配置是 ground：运行积水、坑洞、裂损路面和楼梯相关任务，不同时运行普通物体模型。需要展示普通物体时可显式使用 balanced。两种模式均已进行本地真实模型检查。

不同任务分别负责自己的风险类别，不是把各模型的分数直接加权平均。检测框、提醒事件、声音调度和实际耳机发声是四个不同阶段。

## 三、已完成的验证

1. 早期 Pi 实机：摄像头预览、普通物体识别框和 HyperX 耳机英语提示曾由用户确认正常。
2. 后续本地迭代：增加并整合积水、坑洞、裂损路面和楼梯能力；加入蓝地板、商场反光、黑鞋、圆形地面图案等负例检查。
3. 综合压力测试：125 张图片（119 张实拍、6 张 AI 模拟），约 11.5 分钟累计实模型运行，包含逐图回放、连续场景、画面故障与接口负载。
4. 连续检查：持续楼梯只提示一次；离开再进入可重新提示；黑画面触发画质门控；模拟摄像头中断后恢复；未出现模型错误或过期视觉证据触发的地面事件。
5. 并发访问：三个并发客户端，两次运行共 2,979 次请求，无请求异常；本机预览中位数约 11 FPS，接口 p95 约 20 ms。这些不是 Pi 的性能数字。
6. 普通物体：本地 balanced 模式下，人、椅子、包的指定正例出现相应检测框；无真实距离输入时没有越过距离门控播报物体接近。
7. 重复提醒、优先级、过期处理、队列、距离门控及新评分工具等相关程序检查共 29 项通过。
8. 最新 Pi 部署：212 个载荷文件校验通过，除明确记录的 Pi 调度／音频配置外与已测版本一致。真实 C270 检查 35 秒，60 个稳定状态样本均就绪，四条地面任务无报错；摄像头约 14.9 FPS、预览中位数 11.8 FPS，服务重启计数为零，欠压／降频记录为零。该检查只验证运行，当前镜头朝门框，不能作为真实地面危险识别验收。
9. 网络真实视频：五段连续视频、共 117.67 秒，使用 Pi 配置在电脑回放，未中断 Pi。积水近景、地铁两段上楼、移动道路坑洞均生成事件；明确负例窗口没有误报。发现同一楼梯重复四次提醒，以及移动道路积水有候选却未通过连续确认的问题。没有修补或隐藏这些结果，下一轮优先处理移动跟踪与去重。详见 `pi-real-video-validation-20261031.md`。
10. 用户要求改成真正步行素材后，重新筛选三段正常速度第一视角步行视频，共 146.07 秒，排除原地踩水、固定机位、车载和加速视频。林间楼梯五次事件、柏林台阶两次、过街天桥两次；林间另有一次积水误报。相同类别再次提醒的实际间隔为约 8.0–8.7 秒，来自新跟踪目标，不是定时重复开关。四种确定性冷却情形也已检查。此次没有连续水坑步行正例，不能宣称已验收该场景。详见 `pi-walking-video-validation-20261031.md`。回放启动遇到帧率统计除零，已在本地加入一个状态保护，未热更新 Pi；识别和提醒规则未改。

## 四、下一阶段实行顺序

1. **部署已完成。** 源码、配置、模型权重与英语语音片段已同步，原覆盖文件已备份。服务 `smart-cane-camera` 正常运行；电脑预览地址 `http://127.0.0.1:8010/`，依赖本机 SSH 转发进程。
2. **验收默认 ground 模式的实际场景。** 镜头向下对准地面，复测黑鞋、圆形图案、蓝地面、反光地面等常见干扰；用受控场景确认楼梯及其他风险。需要声音时先把 HyperX 接收器插到 Pi 并开机，再启用音频、验证实际听音。
3. **处理多风险声音调度。** 确认最高风险优先时，仍持续存在的低优先级风险应被跳过，还是在重新确认后补充提示；避免播放已经离开的目标。
4. **固定安装后测试。** 先固定支架与摄像头朝向，再安装到向前推的拐杖；检查移动、抖动、光线变化和不同安装角度对识别的影响，同时记录 Pi 帧率、延迟与声音可懂度。
5. **最后整合 Pico。** 约定距离数据格式、更新时间、方向及异常状态。保留 Pi 路面提醒和 Pico 测距震动独立工作；确需“视觉类别 + 距离”提示时，先确认时间及视野对应，不能把单点测距随意绑定到某个识别框。

暂不增加摄像头数量、训练流程或新场景模型。接机后若出现稳定可复现的问题，先保留样例与日志，再决定是否需要调整规则或训练。

真实视频新增待办：处理楼梯分类观察区域与分割框交替导致的目标重建；检查水坑移动时的前方区域和连续确认。修复前应保留当前五段原始视频、冻结标签和结果作为回归基线，不能只靠增加冷却时间掩盖漏报或重复提示。
