# EE3070 Smart Cane — Raspberry Pi V2 PRD

版本：1.2。日期：2026-10-26，Asia/Hong_Kong。

读者：后续负责实现、模型部署、Pi 调试与验收的 agent。本文是实施要求，不是已实现报告；当前实际进度单独记录在 [验证记录](pi-v2-validation.md)。

## 1. 用户决定与项目目标

在现有 Raspberry Pi 5 项目上升级：**一个 Logitech USB 摄像头，共享取流，同时运行前方物体识别与地面风险识别，由 Pi 输出英语提醒。**

用户负责 Pi；队友负责 Pico、超声波、TFmini-S、测距与独立震动。当前没有 Pico，先完成明确标为模拟的距离触发链路；不修改队友固件。

本次访谈已确认：

- 使用场景是**室外**；先图片/视频验证，再逐项进行真实摄像头路面验证。
- 用户无法提供这些路面场景。实施 agent 自行寻找有来源与许可的公开真实照片/视频，建立明确标注 replay 的模拟；不得将收集素材或训练任务转交用户。照片回放可以验证模型与提示链路，不能代替物理高差、安装姿态或实际室外验收。
- 以下全部地面场景都是 V2 必做目标，可逐项研究和验证，不能只完成坑洞就宣布整个 V2 完成。
- 不训练或微调模型，不把标注训练集或算法研发转交用户；允许现成模型加载、导出、部署和验收参数调整。
- 默认保留**英语播报**，覆盖粘贴 prompt 中的中文示例。
- 用户没有给出硬性截止；实施者自行按依赖推进，不反复追问日期，也不承诺未经验证的交期。
- 不增加第二台相机、硬件采购、麦克风、AI Agent/Gemini、对话、导航或坡度检测。
- 用户后续删去路缘/路面边缘识别；不为它增加模型、语音或验收任务。箱子/杆子是原 prompt 的普通障碍示例，按现成模型支持情况显示，不单独增加模型或列为必达类别。
- 不重写已工作的项目；少依赖、少备用路径、预览及时，后台不能积压旧帧。

### 完成状态

每项能力分别记录：`required_unverified`（必做未验证）、`experimental`（实验实现）、`passed_replay`、`passed_outdoor`、`blocked`。这些状态和模型故障状态分开。

全部场景仍为必做。某项没有适用权重、许可不清、无法在 Pi 运行或效果不足，必须保留为未完成/受阻并给证据；不得用接口、假标签、录制好的提示音或更名模型类别冒充完成。实验性下行台阶/突降也必须有实际实现和实验结果，不能只列候选。

## 3. 必做能力与模型路线

详细来源、已核查文件和缺口见 [V2 模型评估](pi-v2-model-assessment.md)。以下选择是待验证的工程路线，不是效果承诺。

| 需求 | 优先路线 | 验收语义及限制 |
| --- | --- | --- |
| 正常路面 | SegFormer-B0 ADE20K 的 road/sidewalk/path 等区域 | 只输出路面语义/关注区域；不播“安全”，未检出风险不等于正常 |
| 坑洞 | `dronefreak/rdd2022-yolov8n` | 与破损共用一模型；实际 pothole 标签，不估坑深 |
| 破损/不平路面 | 同一 RDD YOLOv8n 的三类裂缝 | 先实现可见破损；裂缝不等于物理高低不平，凸起/松动/不平整仍需另有现成模型及测试，否则此子项未完成 |
| 积水 | SegFormer-B0 的 water，结合地面区域、路径区域及时序 | 仅“疑似积水”；透明浅水、反光、湿路与镜面单独测，不能把所有 water 当水潭 |
| 下行台阶/突然落差 | 必做实验研究项；先验证 stairs/step 语义，再寻找有真实方向/负障碍证据的 RGB 现成权重 | stairs 不等于 down；下行台阶与无台阶突降分别验证，任一不通过就不能标该项完成 |
| 人/椅子/自行车及 V1 包类 | 保留 YOLO11n COCO | 类别可持续显示，但必须通过有效距离与关联规则才能播报 |
| 箱子/杆子（示例，非必达） | 仅在已选模型实际支持时考虑显示 | 不为它们单独加模型；COCO 无独立 box/pole，不能通过改标签宣称支持 |

### 模型选择规则

1. 优先实现 **YOLO11n 物体 + 一个 RDD nano 模型 + 一个共享语义分割模型**，避免每个类别各装一套模型；不增加路缘专用模型。
2. V1 NCNN 路线保留。新增模型先尝试兼容的固定导出；确有必要时引入一个额外的 ARM CPU 运行时并固定版本，不将 NCNN、PyTorch、ONNX、OpenVINO、TFLite 全部堆进常驻程序。
3. 导出可在 Windows 的 `D:\SmartCaneRuntime\` 或对应项目文件夹隔离进行；Pi 不安装整套训练栈。导出不是训练。
4. 先验证一模型的原始输出与标签，再测静态样本，再测 Pi，最后接提醒；禁止只验证下载成功就启用语音。
5. 转换前后使用同一批图比较类别、框/掩码与置信度。各模型独立后处理和阈值；不同模型分数不直接加权成“更可信”。
6. 保存来源、revision、实际文件名、字节数、SHA-256、原始类表、预处理、输出布局、运行时与许可。未核实的项如实留空，不能编造哈希/兼容性。
7. 不因多模型拖慢就默默关闭某个必做场景并宣布 V2 完成。调度、输入和频率调整后仍不达标，记录性能缺口与已测配置。

## 4. 系统行为

### 4.1 单摄像头与室外视野

```text
一台 C270 → 单一 CameraSource（frame_id / 驱动交付时间 / 最新帧）
                    ├→ ObjectDetector → 短时目标跟踪 ─┐
                    └→ GroundDetector → 路径区域过滤 ─┤
MockDistanceProvider / 未来 Pico Adapter ─→ 关联与门控 ┤
                                                    ↓
                       唯一 WarningManager / OutputArbiter
                                ├→ 英语本地语音
                                └→ 实时标注、状态与结构化日志
Pico 自己的测距/震动回路独立运行，不等待 Pi 推理或声音。
```

- 共用采集源；模型各自保留最新待处理帧，队列容量至多一帧，不回放积压。
- 两个任务不要求处理同一 frame_id；关联必须检查真实 frame_id、采集时间与有效期。
- 预览取最新相机画面，叠加仍有效的最近结果；显示各结果帧龄。过期框/掩码立即清除，不能用新底图伪装旧识别已更新。
- 相机高度由现场测量；下倾角以光轴相对水平线为准，比较 0°、15°、25°。不能为了地面完全丢失前方物体视野。
- 各姿态分别配置对象区域和地面路径区域。区域代表图像中的可能行走方向，不是已标定的物理走廊。
- 遮挡、过暗、强模糊或无有效地面时，降低/停止相应视觉判断并显示状态；不以画面下半部默认就是地面。
- 固定支架通过后再装拐杖，测试摆动。无需新增 IMU；不宣称已经知道实时姿态或能准确定位重访风险。

初始验收覆盖白天室外铺装路、阴影与反光/湿路。夜间、暴雨、强逆光等单独标未验收，不把白天结果外推。

### 4.2 地面风险提醒

- 不依赖 Pico 距离即可触发；相机/模型/有效地面和时序证据仍必须满足。
- 将坑洞框或分割掩码映射回原图，再判断其是否与路径区域相关。采用真实交叠/位置规则，不能只看类别存在。
- 初始规则：至少 2 个不同分析帧的连续有效证据，时间窗口 2 秒。未命中清空连续证据；按模型频率留档调整。
- 采用短时图像区域/IoU 事件跟踪即可，不默认增加 ReID 神经网络。相机大幅移动、遮挡或超时后不维持虚假的世界坐标身份。
- 同一事件持续存在只提示一次；离开约 2 秒后再出现且满足至少 8 秒冷却，才允许重新提示。不同事件保留各自 ID，并受全局音频节流。
- 必须记录首次可见证据、确认、排队与播放时间。“提前”表示在可见范围中及时提示，不承诺未知米数的预警距离。
- 正常路面只显示状态；不播报“路径安全”“可以前进”，不根据未检出目标输出正常证明。

### 4.3 物体识别、距离门控与关联

V2 要改变 V1 的触发：**看到椅子本身不再自动发声。** 距离无效、缺失、过期或远于阈值时继续显示类别，但不发物体类别语音。

V1 配置可以作为显式选择的回归入口保留原行为；V2 运行时不能因为距离缺失而自动退回 V1 的视觉直接播报。

初始演示参数（仅软件测试值，不是安全距离）：

| 参数 | 初始值 |
| --- | --- |
| 进入近距离状态 | 有效距离 ≤ 1.00 m，连续 2 个不同样本 |
| 离开近距离状态 | 有效距离 ≥ 1.20 m，连续 2 个不同样本 |
| 同一近距离事件 | 只报一次，直到离开近距离状态后重新进入 |
| 再次提示冷却 | 8 秒；迟滞带内不重新武装 |
| 距离接收有效期 | 500 ms；设备采样时效若可确定还需另查 |
| 视觉关联有效期 | 对象结果不超过 500 ms；与距离接收时间差先限制 250 ms |

- **进入近距离状态不等于知道测到了哪个视觉物体。** 不得把最近框、最大框或画面中唯一物体默认当作被测对象。
- 有已确认的传感器朝向、安装关系与投影区域，时间一致、区域内只有明确匹配候选且跟踪稳定，才允许类别提示。
- 多目标、未知方向/FOV、相机移动后映射失效、时间不一致等情况：只要真实/模拟距离本身仍有效且进入门限，用通用 **“Obstacle ahead.”**；不能捏造 Chair/Person。
- 没有有效距离时不发普通物体语音；地面提示仍独立。相机失败但有效距离可用时，通用提醒可以保留，不能使用旧的物体类别。
- Mock 端也必须遵守关联规则。命名为椅子的成功演示需要显式模拟的已校验映射/关联夹具；没有这种证据时 90 cm 应通用提醒，而不是椅子提醒。
- 不做相机/超声/激光距离的随意加权。视觉在本阶段提供类别与区域，Pico 提供测距；声称米数的来源必须是距离提供者。

### 4.4 唯一语音管理

- 两类视觉任务只产生事件，所有播放都经同一个仲裁器和同一个可停止播放器，禁止同时运行旧 Camera Audio 与新的播放回路。
- 优先评估复用 `OutputArbiter`。PipeWire 后端实现 `play/stop/busy`，保留 HyperX 实测路径；普通的阻塞 `subprocess.run` 不能冒充可抢占播放。
- 已验证的严重负障碍事件优先于一般积水/破损和普通类别提醒；优先级是演示策略，不是已验证的安全评级。所有 Pico 震动均不受语音排队影响。
- 高优先级事件可终止低优先级播放；停止后检查仍有效的当前事件，不机械重播已经远离的旧提醒。
- 待播队列有界，建议至多 2 条不同有效事件；同事件去重。全局普通提醒间隔起点 3 秒，紧急事件可越过间隔。
- 日志/预览保留有效的未播事件，不把“被抢占/过期/未排入队列”记为已经播出。
- 默认英语短句，本地 WAV，运行时无需云端 TTS。没耳机可用 Console/事件模式测试，但明确 `audio=disabled`，不能称听音通过。

| 情况 | 固定短语示例 |
| --- | --- |
| 坑洞 | Possible pothole ahead. Watch your step. |
| 疑似积水 | Possible puddle ahead. |
| 已识别可见破损 | Damaged pavement ahead. Watch your step. |
| 真实支持的不平整 | Uneven ground ahead. Watch your step. |
| 仅楼梯语义 | Possible stairs ahead. |
| 已通过方向实验 | Possible steps down ahead. Stop and check. |
| 已通过突降实验 | Possible drop ahead. Stop and check. |
| 匹配对象 | Chair ahead. / Person ahead. / Bicycle ahead. |
| 距离有效但无可靠匹配 | Obstacle ahead. |

短语只在对应能力已启用、证据成立时使用。声音音量和短语长度由现场确认，减少遮盖环境音；不把现有封闭式耳机用于演示等同已完成室外可用性验证。

## 5. 接口与模拟协议

### 5.1 距离接口

使用一个小型 `DistanceProvider` 接口，如 `latest(now) -> DistanceObservation | None`，提供 `start/close`；视觉端不依赖串口实现。

`DistanceObservation` 至少含：`sample_id`、`source=mock|pico`、`distance_m`、`valid`、`received_monotonic`、可选 `device_ms`、`sensor_id`、`direction`、`region_id`、`calibration_id` 和 `reason`。

- Mock 使用固定脚本 `250 → 180 → 120 → 90 → 50 cm`，另有退出、反复越界、无效、丢包、错向、过期和多对象脚本，可重复运行。
- 默认不自动生成近距离；必须显式启用 `mock`。预览、事件和日志持续标 `MOCK DISTANCE`。真实提供者失败时禁止静默切换 mock。
- 源码中的随机 `SimPicoLink` 可以保留用于旧测试，但不能代替本次确定性的 MockDistanceProvider。

### 5.2 复用已有 Pico JSONL

仓库现有帧：

```json
{"t":"d","f":123,"u":250,"g":180,"gs":900,"ms":12345}
```

`f/u/g` 是现有通道，距离单位 cm，负数代表无效；`ms` 是 Pico uptime，不是 Pi 单调时间。解析后内部统一 m。V2 先适配当前协议，不擅自改变队友固件。

未来协商的可选版本扩展可以包含 `seq/valid/sensor_id/direction/region_id`，但**不假定当前 Pico 已发送**。实际方向由双方确认的安装配置补充，缺失时为 `unknown`。

接收时记录 Pi 本地时间；不能直接用 Pi 时钟减 Pico uptime。另记录连接/接收超时与设备样本序号，检查重复、倒退和设备重启。USB Serial 优先沿用现有适配；UART 留接口说明，不在无硬件时宣称联调通过。

### 5.3 统一观察与事件

视觉观察至少包含 `run_id/frame_id/captured_monotonic/task/model_id/model_revision/raw_label/confidence/bbox_or_mask/valid_until`。框和掩码坐标明确归一化或像素制，不混用。

事件应包含：

```json
{
  "schema_version": "2.0",
  "event_id": "run:object-17:near-1",
  "kind": "OBJECT_NEAR",
  "source": "vision+mock_distance",
  "frame_id": 216,
  "track_id": "object-17",
  "object_class": "chair",
  "distance_m": 0.9,
  "distance_sample_id": "mock:6",
  "association": "matched_simulation",
  "calibration_id": "fixture-only",
  "phrase_id": "chair_ahead",
  "priority": "SAFETY",
  "ttl_ms": 1500
}
```

上述是模拟契约示例，不是实测记录。匹配不成立时 `object_class=null`，使用 generic phrase；地面事件无需距离，`distance_m=null`，不能塞入相对深度或框面积充当距离。

后续 Pico transport 不得误将 mock 事件当真实传感器；Pico 震动接口在本轮关闭，尤其不发送“解除/接管”队友反馈的命令。

## 6. 性能、故障与数据要求

以下是待 Pi 实测的工程目标，允许先调参，**达不到须报告，不准写保证值**：

| 指标 | 初始验收目标 |
| --- | --- |
| 摄像头采集 | 640×480，15 FPS 起点；记录实际采集率，不只记录请求值 |
| 实时预览 | 持续更新，目标 ≥ 5 FPS；结果过期时清框，采集至标注输出 p95 ≤ 500 ms |
| 物体分析 | 全部启用配置下 ≥ 3 FPS |
| 地面分析 | 每个已启用必做类别的有效分析机会 ≥ 1 Hz；分别记录，不用多个模型的总频率充数 |
| 风险确认 | 从首次有效可见证据到确认事件 p95 ≤ 3 s；报告时间过滤等待，不只报推理耗时 |
| 距离门控 | 新有效距离到事件决策 p95 ≤ 200 ms，已有视觉结果且关联成立时 |
| 抢占 | 高优先级事件提交到旧播放停止，软件观测目标 ≤ 250 ms；声波实测另列 |
| 稳定性 | 全功能配置运行 10 分钟，按用户既有时间偏好；不自动延长成 20 分钟 |

同时记录采集/每模型推理/事件 FPS、p50/p95 时延、掉帧、各结果帧龄、CPU、RSS、温度、欠压与运行 ID。驱动交付时间不等于曝光时间；JPEG 编码完成不等于浏览器显示；播放器启动不等于声波开始。

先比较单模型，再比较全部启用的最终组合。按周期处理最新帧、错峰运行、固定线程预算，禁止每模型无限线程或队列。只有实测需要才提高并发；不要为性能引入复杂消息中间件。

模型独立故障降级：地面模型失败不伪装正常路面，也不必停止仍有效的物体分析；缺少距离停止物体类别语音但不停止地面预警。相机断开清除全部视觉证据、关联和待播视觉提醒，保留明确故障状态。

源标识必须包括 `live_camera|replay` 与 `mock|pico|none`。回放不能标直播，规则夹具不能当视觉模型证据。

默认不连续保存视频/图像、不上传画面。评价材料须单独指定，截图/日志/模型/生成音频/凭据排除 Git。所有 Windows 下载留 D 盘相应目录；`sources/` 同步参考文件只读。

## 8. 验收矩阵与完成条件

### A. 模型能力

每个必做地面类别分别准备至少 10 个独立正例与 10 个易混淆负例片段；不把一段视频的连续帧当多个独立试次。先回放，再真实室外各记录一次。

素材由实施 agent 准备，先保存来源、许可、文件哈希与人工审阅标签，再运行模型。开发集上调过参数的结果不能当独立验收；重复播放同一照片不增加独立样本数。模拟只改变输入源，不按预设答案伪造检测框或语音。

初始工程门槛：每类至少 8/10 正例在首次有效可见后 3 秒内产生正确事件；每类负例误触发不多于 1/10。背景无目标时另测 5 分钟，错误语音事件不多于 1 次。没有足够样本标未验收，不能用作者 mAP 替代。

- 正常路面：必须能给语义结果，同时“没有检出风险”不能被当作正常标签真值。
- 破损与实际不平整分开；下行台阶与普通楼梯、突然落差分开。
- 积水负例包含反光、阴影、湿但无可见积水、深色路砖；不估水深/湿滑程度。
- 楼梯/落差负例包含上行台阶、平面条纹、斜视栏杆、阴影边缘。仅检测到 stairs 不能通过 downward/drop 的验收。
- 人、椅子、自行车和已启用箱/杆分别验证；未启用类别显示未支持，而不是误读别的标签。

### B. 距离、关联与调度

| 场景 | 必须行为 |
| --- | --- |
| 椅子可见，模拟 250/180/120 cm | 有框，物体语音保持静默 |
| 有明确模拟匹配证据，90 cm 连续有效 | 仅一次 Chair ahead；日志标 mock 与模拟关联 |
| 90/110/95/105 cm 抖动 | 不因越过 100 cm 反复播报 |
| 退到 120 cm 以上后再接近 | 满足迟滞、冷却后可产生新事件 |
| 有效 90 cm，但未知方向或多候选 | 仅通用 Obstacle ahead，不任意点名 |
| 视觉关联已过期/对象离开 | 不播旧类别；距离有效时最多通用提示 |
| 没距离、无效值、丢包、旧样本 | 不播物体类别，地面链路仍工作 |
| 坑洞有效，但没有 Pico | 正常产生地面语音事件 |
| 坑洞与近物同时出现 | 按优先级、不叠音；较旧/已失效事件不补播 |
| 高优先级到来，低优先级正在播放 | 可停止并抢占，有明确开始/中断记录 |
| 摄像头重复失败 | 清旧证据，但不能每轮把尚未播放的故障音清掉 |
| 距离程序关闭或连接失败 | 明确状态；不自动开启模拟数据 |

### C. 实机与安装

- Pi 上同一进程只占用一个摄像头，页面刷新不重复打开设备。
- 模型/相机故障、恢复、真实拔插和程序重启分别记录，模拟故障不写成物理拔插。
- 断开互联网后本地识别、模拟距离与 WAV 仍工作；避免为了测试破坏当前唯一 SSH 后失去观察手段，可在可恢复条件下执行。
- 三个角度记录前方与地面可见范围、近处盲区、照明及结果；选定最终姿态。拐杖摆动后再测，不能只交桌面结果。
- 最终全部启用配置运行 10 分钟，报告真实结果与供电；不将 CPU 推理完成当作声波/网页端到端延迟。
- 真实 Pico 不在场，因此只能完成 Pi 端和模拟契约验收；保留真实测距关联、时钟/方向标定及联合演示为待联调，不能标已通过。

### D. V2 Done

所有必做地面能力都具备实际实现、对应模型证据、Pi 组合性能与室外记录，物体距离门控及唯一英语语音链路通过，V1 回归保持，交接文档齐全，才能标 V2 全部完成。仅回放通过、仅接口完成或某必做项 blocked 时，只能报告部分完成。
